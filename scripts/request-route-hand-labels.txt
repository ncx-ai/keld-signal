# Hand labels — PER-REQUEST routing class. 120 inference requests, blind, stratified 15/class.
#
# Corpus: a second engineer's real Claude Code transcripts (corpus A) ($KELD_CORPUS_A), 298 files after
# observer-session exclusion, 8,193 requests. Sample drawn by scripts/request_gold_sample.py
# (seed 11), committed at e1df5e6 BEFORE a single label was written. The blind file carries no
# class, and the key was held back in a separate file. Both orderings are provable from git.
#
# ⚠️ STRATIFIED, NOT RANDOM — 15 per class. A proportional draw is ~32% operate / 29% retrieve
# and gives single digits for author_prose and delegate, the classes that decide routing
# quality. **No base rate may be read off these labels.** What they measure is PER-CLASS
# precision of the deterministic classifier, nothing else.
#
# THE QUESTION EACH LABEL ANSWERS: which model capability did this one inference stress?
# That is the decision a per-request router makes. Not "what kind of work is this block".
#
# CLASSES (8, asserted to cover the population — there is no `other`):
#   retrieve      reads/searches/inspects existing state; args are a path or a query
#   operate       mechanical side effect, no authored content (git add, mkdir, docker, ledger)
#   verify        runs a check on correctness (tests, lint, build, type-check)
#   author_code   produces source/config content, in a file OR inline in a tool argument
#   author_prose  produces document content (docs, reports, commit messages, PR bodies, Notion)
#   synthesize    long prose to the caller, no tool — reports, findings, explanations
#   delegate      dispatches a subagent or skill with an authored prompt
#   acknowledge   short prose to the caller, no tool
#
# RULES, fixed before labelling:
#  1. Judge by what the model had to PRODUCE, not by what the work was about.
#  2. ⚠️ AN AUTHORED PROGRAM IN A TOOL ARGUMENT IS `author_code`, whatever the program DOES.
#     A `python3 -c` that crops an image or inspects XML still required writing correct Python,
#     which is the capability a router would be substituting. A shell pipeline of standard
#     utilities (grep/ls/find/git) is NOT authoring. This rule was written down after the
#     first four such cases were labelled inconsistently, and all of them were revisited.
#  3. A commit message or PR body IS authored prose. `git commit -m "$(cat <<EOF ...)"` with a
#     real message is author_prose; `git add` + a one-line message is operate.
#  4. Mixed requests take the DOMINANT authored content, not the first tool.
#  5. Prose-only requests split on intent, not token count: a structured report is synthesize
#     even when short; a status line is acknowledge even when it lists commits.
#
