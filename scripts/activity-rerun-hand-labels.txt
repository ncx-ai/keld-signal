# RUBRIC, fixed here before labelling:
#
# 1. The question is what the AI+user system SPENT THE HOUR DOING, judged from what was said.
#
# 2. HIERARCHY OF DEMAND, not volume. If the hour sustained authoring it is `generate` however
#    much reading preceded it. (`prose-activity` Amendment 1 measured the volume trap: a
#    dominant-class rollup produced a 95.4% majority baseline, unbeatable by construction.)
#
# 3. THE ONE CONTENTIOUS CALL, resolved exactly as attempt one resolved it, and stated here so it
#    is not a post-hoc choice: editing code to IMPLEMENT a feature, a fix, or a refactor with new
#    behaviour is `generate` — the gloss names "code" explicitly. `transform` is reserved for
#    changing the FORM of existing content while preserving its substance: reformat, rewrite,
#    translate, convert, summarize. Attempt one's post-hoc collapse A bounded how much this call
#    can matter (+0.013 conceding it entirely) and it is scored again here as a declared
#    diagnostic, so the verdict does not rest on it either way.
#
# 4. `review` is checking EXISTING work for errors: code review, verifying a claim someone made,
#    running a suite to find out whether something is broken, auditing.
#
# 5. `analyze` is reasoning over inputs to reach a conclusion: measuring, evaluating options,
#    computing a number, deciding. The output is a judgement, not an artifact.
#
# 6. `retrieve` is looking things up — where does X live, what does Y do, gather the facts.
#
# 7. `converse` is discussion, brainstorming, or question-answering that produces no artifact.
#
# 8. When two readings apply, pick what the hour was FOR — the demand the user made — not the
#    incidental supporting work. Every window gets exactly one label; there is no abstention,
#    matching attempt one (which had none).
