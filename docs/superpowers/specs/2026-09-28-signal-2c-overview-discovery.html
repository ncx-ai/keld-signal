1 · Hypothesis & scope

The why

  • Problem: The page answers "what happened today" only. It has no range, no trend and no split.
  • Who feels it: An engineer checking their own AI spend at the end of a week.
  • Business value: One pane answers how much, on what, and when — for a day, week or month.
  • Hypothesis: The existing ledger backs every 2C Overview number with one additive field. Falsified if a tile or bar needs a new store, or disagrees with /v1/ledger.

Goals

  • G1 — The 2C Overview on real data: range control, four tiles, cost & volume chart, 20-minute histogram.
  • G2 — Overview is where Signal opens. Today keeps its content under a new name, Focus blocks.
  • G3 — Nothing else in the UI changes: shell, nav style, Projects, Integrations, Settings.
  • G4 — No new store, no new route, no new pattern. One additive field on one route.

Technical design

  • Data: No migration. Store.Read selects dim_repo, dim_branch. Old rows with empty dims get no key and read "no repository".
  • API: Blocks gain optional "dims": {"repo","branch"}. Additive; auth unchanged. contracts.md is edited first, per its own rule.
  • Read path: Overview fetches rangeLedgerURL(range, now) on entry and on range change. The last range picked lives in localStorage (page convention 3); 7d only on first open. The response caches under its own key.
  • Layout: 2C's Overview — title + range buttons, four tiles, chart with its split links, histogram strip. Built in the page's existing tokens and type.
  • Invariants respected: "est." on every dollar figure. An absent cell is never "failed". Headline tokens exclude request. No prompt text reaches the page. Vocabulary denylist. WebKit rendering, since Tauri hosts the page.

Objections

Why touch Go at all for one page?
Fair — nearly all of this is page work. By repo has no other source, though. The column is already stored; the change is one SELECT and one optional field.
Why two ledger fetches instead of one?
One would be simpler code. Two means Focus blocks cannot change by accident, which is the scope. It costs ~90 ms, and none at all when the range is Today.
Won't "By project" look mostly empty?
Yes, on this Mac: 59% of blocks have no project. Hiding that bucket would overstate attribution. The honest bar shrinks as projects get defined.
Is 1m safe against the 2000-row cap?
Here it is 905 rows in 91 ms. A heavier machine could hit the cap. When it does, the page says so and marks the missing days, rather than drawing zeros.
Won't people miss Today as the first screen?
Possibly — it is a habit change. Focus blocks is the next nav item, bookmarks still work, and every pane still shows a failure.
Why no charting library?
The page loads nothing but Google Fonts, by contract. 2C draws bars and one line. CSS and one SVG polyline cover that.
