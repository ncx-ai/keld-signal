1 · Hypothesis & scope

The why

  • Problem: Codex sessions reach Atlas as telemetry only. No Codex prompt has ever been enriched, and no Codex block has ever been cut.
  • Who feels it: Any org that runs Codex. The Alpha account sees activity for Codex and classifications only for Claude.
  • Business value: Workstreams, blocks and project attribution cover every tool keld signal setup configures, not one.
  • Hypothesis: If the sidecar reads a normalised turn record instead of the Claude line, a Codex reader of a few hundred lines yields the same workstreams Claude gets, and the Claude path stays byte-identical.

Goals

  • G1 — A Codex session publishes blocks with attributed workstreams.
  • G2 — Claude Code and Cowork rows do not change by one byte.
  • G3 — A third tool is a reader plus one eligibility entry. Nothing else.

Explicit exclusions

  • A Gemini reader. Same shape, separate page; see section 8.
  • Embedding or porting codeburn. Its Codex parser is the field-mapping reference and nothing more.
  • Any change to Codex telemetry, the proxy, or Atlas. Atlas already renders workstreams for any source.
  • A Codex prompt hook. Codex fires no prompt-submit hook; the watcher is the only capture path.
  • Keyword or heuristic classification of Codex turns. The workstream dimensions are counted, as for Claude.
  • Branch for Codex. Rollouts carry no branch field; the dimension stays unattributed until measured otherwise.

Technical design

  • Data: No schema change. Codex rows use the existing levels. No STATE_VERSION bump: AC-2 proves Claude stores need no reparse.
  • The record: ts, session, scope_root, line_id, prompt_id, role, cwd, branch, model, sidechain, skill, mcp_server, mcp_tool, text, think_chars[], tool_calls[{name, input}], usage, request_id. Text stays in memory; only lengths and terms are stored, as today.
  • API: /ingest and /analyze unchanged. The reader is chosen by path root, the same table AnalyzeRoots already builds.
  • Read path: workstreams, blocks, dynamics and prior consume rows. None of them learns the word Codex.
  • Invariants respected: text never crosses (unchanged); the term level reads Codex text under the same v18 rule; path confinement already covers ~/.codex/sessions; single-flight untouched, this path issues no inference.

Objections

Why refactor six modules first? Ship the Codex reader and refactor later.
That is option A, and it is faster by days. The cost is a second shape in six places, which is the drift class that produced the uuid-only index bug. AC-2 makes the refactor safe: one golden dump, zero rows may differ.
Isn't the golden dump just freezing today's bugs?
Yes, and that is the point. This page changes where the code reads from, not what it computes. A bug fixed on the way would be invisible inside the refactor; fix it in its own commit, and regenerate the dump there.
Why not codeburn? It already has 46 parsers.
It has 46 parsers behind a CLI with no library exports, emitting aggregated cost. We need events with timestamps, paths and turn ids inside a Python process. Reading its Codex parser saved a day of field-hunting; running it would cost a Node runtime in every install.
The record is the Claude shape with new names. Is that really neutral?
Partly true. Its fields are what the extractor consumes today, which was written for Claude. It is neutral where it matters: Codex fills every field the workstream dimensions need except branch and skill, and those stay unattributed rather than faked.
Does Codex text now leak into named_terms?
Proper nouns from Codex messages publish as term plus count, exactly as Claude's do, and the installer Read Me states that for all sources. No text, span or offset crosses. This page adds a source, not a class of data.
Two of 1,848 turns had no turn_context first. Why not treat them as broken?
A dropped prompt is the failure we are fixing. The fallback id is worse, and it is counted, so if the 2 ever become 200 the counter says so before Atlas does.
