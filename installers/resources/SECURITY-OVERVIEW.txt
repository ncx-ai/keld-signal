KELD SIGNAL — SECURITY & PRIVACY OVERVIEW

Last updated: September 14, 2026

Keld Signal gives your organization visibility into how AI coding tools
are used — without your prompts, code, or AI responses ever leaving your
computer. This page summarizes exactly what is collected, what is not,
and how the software protects your data.


WHAT GETS INSTALLED

  keld                 A command-line tool for sign-in, setup, and status.
  keld-agent           A per-user background service that reads your AI
                       sessions locally, derives the signal described
                       below, and sends only that.
  keld-agent-sidecar   The on-device analysis service keld-agent talks to
                       over loopback. A standard install needs no
                       machine-learning model and never downloads one. (An
                       organization may opt a machine into a mode that
                       loads one; that too runs entirely on your computer.)
  Keld Signal.app      macOS only. A desktop window onto the agent's own
                       local status page: what was collected today, which
                       projects it was attributed to, and whether the agent
                       is healthy. It holds no credential and makes no
                       network request of its own.

Where they go:

  macOS     keld, keld-agent, the onboarding script, VERSION, README and
            CHANGELOG in /usr/local/keld, with keld and keld-agent linked
            from /usr/local/bin. Keld Signal.app in /Applications. The
            analysis service in ~/.local/bin/keld-agent-sidecar, fetched
            by the onboarding script after the package installs. The
            background service registered as a per-user LaunchAgent
            (~/Library/LaunchAgents/co.keld.agent.plist).
  Windows   keld, keld-agent, the analysis service and the onboarding
            script in %LOCALAPPDATA%\Programs\keld, plus a logon task
            that starts the agent under your account.
  All       Configuration, sign-in tokens, logs and local state under
            ~/.keld, readable by your user only.

The macOS installer asks for an administrator password to place files in
/usr/local and /Applications; the background service itself runs under
your own account. On Windows no administrator privileges are required.


DATA THAT IS COLLECTED (USAGE TELEMETRY)

For each AI-tool event, the following metadata is reported to your
organization's Keld Atlas service:

  - Model used and per-request token counts (input, output, cache read,
    and cache creation)
  - Notional cost — a list-price equivalent for reporting purposes only;
    it is not a charge (in particular, not on flat-rate plans)
  - Session id, request id, and request duration
  - Your work email, terminal type, and AI tool version
    (Claude Code / Codex / Gemini CLI)
  - The event type of each event (e.g. api_request, tool call)

DATA THAT IS DERIVED ON YOUR COMPUTER (ENRICHMENT)

The keld-agent service reads AI-session transcripts locally and reports
derived, non-textual signal about each stretch of work (a "block" of up
to 20 minutes) and each prompt:

  - Which project, repository branch, model, programming language,
    output type, skill and tooling the work belonged to — counted from
    tool-call metadata, each with a confidence and an evidence count
  - Which files and directories of the repository were touched
    (paths relative to the repository, never their contents)
  - Token counts and notional cost per block
  - A sensitivity category (see below) and prompt length in characters
  - Proper nouns that appear in messages — product, project and,
    sometimes, people's names — as a term and a count, never with any
    surrounding text, position or offset

Where an organization has opted a machine into the model-backed mode,
per-prompt labels are added: task type, domain, activity type,
work/personal, inferred business function and subcategory.

The prompt itself is never transmitted — these derived values are the
only output that leaves your computer.

DATA THAT IS NEVER COLLECTED

  - Your prompt text
  - Your source code or file contents
  - The AI's responses
  - Unmasked sensitive content of any kind

If the on-device analysis detects sensitive content in a prompt (emails,
credentials, API keys, government identifiers, and similar), only the
category of what was detected is reported, with a short, non-identifying
redacted hint (e.g. "***@example.com") — never the detected value or any
surrounding prompt text. This redaction is always on and is not
configurable — not by you, your organization, or Keld. A detected
credential always forces the prompt's sensitivity classification to
"secrets".

One organization-level setting ("include_entity_text", OFF by default)
allows short, non-sensitive subject-matter terms (e.g. a technology or
product name) to accompany the derived labels. It is controlled by your
organization's administrator and never affects sensitive-content masking.


HOW THE SOFTWARE PROTECTS YOUR DATA

  On-device processing   All prompt analysis and ML inference run locally.
                         Raw transcripts are read on your machine and
                         never uploaded.
  Masking before send    Masking is enforced in the agent immediately
                         before publish — after classification, before
                         any network transmission.
  Encrypted transport    All communication with Keld Atlas uses HTTPS/TLS.
  Local-only service     keld-agent listens only on 127.0.0.1 (loopback)
                         and requires a per-user secret; it is not
                         reachable from the network.
  Credential hygiene     Sign-in uses a browser-based device-authorization
                         flow — your password is never entered in the
                         terminal. Tokens are stored under your user
                         profile (~/.keld) with user-only permissions and
                         can be revoked from Keld Atlas at any time.
  Safe configuration     Every AI-tool config file the installer modifies
                         is backed up first (~/.keld/backups). "keld
                         signal uninstall" cleanly removes Keld's changes.
  Signed releases        macOS packages are Developer ID-signed and
                         notarized when released; binaries are built and
                         published from CI.
  Open source            The complete client source code is available for
                         inspection at https://github.com/ncx-ai/keld-signal.


GOVERNANCE & COMPLIANCE POSTURE

  - Data minimization by design: only metadata and derived, masked labels
    are collected — never content. This supports your organization's
    obligations under privacy regulations such as the GDPR and CCPA.
  - Purpose limitation: collected data is provided solely to the
    organization holding the Keld subscription, for AI-usage visibility
    and governance.
  - Organization control: enrichment behavior is governed centrally by
    your organization's administrator and applied to all agents within
    minutes.
  - Identifiability: telemetry includes your work email so your
    organization can attribute usage; questions about how your
    organization uses this data should go to your administrator.
  - Removal: uninstalling via "keld signal uninstall" plus the platform
    uninstaller removes the software, its configuration changes, and its
    background service; on macOS, drag Keld Signal.app to the Trash.
    Issued tokens are revocable server-side.
