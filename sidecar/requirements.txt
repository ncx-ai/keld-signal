# Exact pins, not a trailing-wildcard series (e.g. the old `fastapi==0.115.*`):
# a wildcard on the minor component only floats within a series upstream has
# already abandoned, so it silently freezes forever once the series ends —
# these two sat 26 (fastapi) and 20 (uvicorn) minor versions behind for over a
# year with nothing failing. Reproducibility for a PyInstaller-frozen binary
# matters more than auto-drift here; scripts/check_dependency_staleness.py
# (wired into CI, see .github/workflows/ci.yml) is the process that keeps an
# exact pin from rotting silently the same way again.
#
# spacy/wordfreq/gliner2 carried the same risk (a `3.8.*`/`3.1.*` wildcard series, or no
# constraint at all) until pinned exactly here — they feed the ML backend and the analysis
# package's `term` level, so a silent resolver drift there is exactly as unreproducible as the
# fastapi/uvicorn incident above.
fastapi==0.141.1
uvicorn[standard]==0.52.4
gliner2[local]==1.3.2

transformers==5.15.1

# torch is deliberately NOT pinned here. ci-freeze-linux.sh installs it first from the

# make the two installs interact in a way that differs per platform — the Linux job would
# be resolving against a different index than macOS and Windows. Constraining torch
# belongs with that script, not here; see the follow-up note in sidecar/README.md.

wordfreq==3.1.1

# `numpy>=1.19.0,<2.5.0` dependency, and this venv runs numpy 2.5.0 under
# torch 2.12.1+cu130 — so 2.2.363/2.2.364 SILENTLY DOWNGRADE numpy to 2.4.6

# does NOT reproduce here — spacy 3.8.15, parser_model and en_core_web_sm NER were
# all verified working on numpy 2.5.0 in this venv. Revisit when upstream lifts the

# 2.5.x without re-running the torch/GLiNER2 check.
presidio-analyzer==2.2.362

# ⚠️ psutil is a RUNTIME dependency and was satisfied only by ACCIDENT until now.
# worker_manager._default_rss / _default_parent_rss / _default_ram read process
# and system memory through it, and those are what the whole memory guard rests
# on — the RSS ceiling, the parent reserve, the pressure eviction (AGENTS.md,
# "Resource safety"). It was never declared here; it arrived transitively via
# accelerate/peft, which come in behind gliner2[local]'s torch stack.
#
# That is fragile in the one direction that matters. The imports sit OUTSIDE their
# try/except, so a build where accelerate or peft stops depending on psutil would
# not degrade the guard — it would raise ModuleNotFoundError from inside it. CI
# found this: the sidecar-tests job installs deliberately without torch/gliner2,
# so it has no accelerate, so it had no psutil.
psutil==7.2.2
